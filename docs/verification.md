# Результаты проверки

Проверено 28 октября 2026 года после изменений диагностики, readiness и контрактных тестов. Все результаты ниже относятся к локальному запуску; результаты удалённого GitHub CI в этот отчёт не включены.

## Выполненные команды

Среда: Go 1.27.3, macOS arm64, отдельная PostgreSQL 18.1. Тестовый владелец имеет DDL и CREATEROLE. Контейнерные сценарии выполнены в Docker Desktop 29.5.2 с PostgreSQL 18.6.

| Команда | Результат |
| --- | --- |
| make generate-check | PASS: DTO не расходятся с OpenAPI |
| make vet | PASS |
| make test | PASS, включая контрактные тесты в internal/httpapi |
| make race | PASS, гонок не обнаружено |
| make integration | PASS с TEST_DATABASE_URL отдельной тестовой БД, детектором гонок и count=1 |
| make build | PASS: собраны server и migrate |
| make vuln | PASS: govulncheck v1.9.0 — No vulnerabilities found |
| make deploy-check | PASS, включая 40 readiness-проб |

Команды generate-check, vet, test, race, integration, build и vuln выполнены последовательно через make с указанным TEST_DATABASE_URL; deploy-check запущен отдельно. Недоступных обязательных проверок нет. Интеграционные сценарии создавали случайные схемы; Docker-проверка — отдельный случайный Compose project. Чужие контейнеры не использовались. Дополнительно прошли go vet с тегом integration и 20 повторов конкурентных сценариев readiness с детектором гонок.

## Новые сценарии

- Классификация неизвестной ошибки, context.Canceled, DeadlineExceeded, PostgreSQL и отказа подключения; SQLSTATE сохраняется отдельно. Неверный формат SQLSTATE не попадает в лог. Тест с Error(), вызывающим panic, подтверждает отсутствие неявного форматирования произвольной ошибки.
- POST/GET/PUT возвращают безопасный 500 при внутренней ошибке. ERROR и INFO завершения содержат один request_id и операцию. Синтетические секреты в DSN, заголовке, теле, query string и полях PgError отсутствуют в логе и внутренних ответах.
- Паники HTTP и readiness оставляют символический стек с исходными файлами и строками без panic payload. После паники readiness не остаётся заблокированным.
- На старте проверены этапы повреждённого DSN, занятого адреса, недоступных сертификатов и отсутствующего леджера. Для последнего сохранён SQLSTATE 42P01 с операцией check_schema. Транспортный logger не пересылает сырой текст net/http.
- На реальной advisory-блокировке PostgreSQL проверен короткий QUERY_TIMEOUT: ERROR содержит deadline_exceeded, SQLSTATE 57014 и request_id даже при ещё не истёкшем внешнем deadline readiness. После снятия блокировки проверка снова проходит.
- 40 конкурентных readiness-запросов разделяют одну проверку. Успех и ошибка кешируются на 1 секунду; после реального истечения TTL проверяются отказ и восстановление. Отмена и deadline ожидающего не отменяют общий цикл; собственный deadline и повтор после ошибки также проверены.
- 17 сценариев HTTP-контракта проверены по OpenAPI через kin-openapi v0.142.0: минимальные/полные POST и PUT, GET, отсутствие записи, конфликт и ошибки входных данных. У корректных запросов проверяется схема. У отрицательных — ожидаемый отказ и отсутствие обращения к хранилищу. Все ответы проверяются по статусу, Content-Type, заявленным заголовкам и JSON-схеме.
- Семь контрольных мутаций ответа подтверждают обнаружение неверного статуса, Content-Type, отсутствующих Location/Cache-Control/X-Request-ID, обязательного свойства и повреждённого JSON.

Существующие тесты строгого JSON, правил MD5, полной замены PUT, временных полей, конкурентных записей, миграций и защиты схемы также прошли. JSON-парсер, мигратор и SQL репозитория не изменены. Контрактные тесты включаются в CI существующими командами make test/race/integration без отдельного ручного шага.

## Docker

Deploy-check проверил bootstrap с паролями со спецсимволами, 40 readiness-проб, повторный up/build с сохранением записи и дат, nonroot/read-only runtime, ошибки конфигурации и CLI, защиту down, восстановление выдачи прав, отключение и запуск PostgreSQL без перезапуска приложения, Bearer/429 бизнес-API, доступность TLS-ключа, доверенный HTTPS и отказ bootstrap при пустых паролях. Проверяемые выводы не раскрыли синтетические пароли или токен. Созданные проверкой контейнеры, том и образ удалены.

## Ограничения

Прикладной кеш может отражать состояние БД с задержкой до TTL 1 секунды. Проверка БД обязана соблюдать контекст; её дедлайн не является гарантией точного времени ответа при остановке планировщика или подтверждении отмены драйвером. Штатный pgx ограничивает ожидание и SQL и допускает до 250 мс на подтверждение отмены.

Проверка схемы не доказывает семантическую эквивалентность CHECK после произвольного изменения администратором с сохранением имён и колонок; владелец схемы остаётся доверенной ролью. Потеря сети около COMMIT может оставить результат записи неизвестным. Эти ограничения не менялись.

В этом прогоне не выполнялись длительные fuzz-мутации, нагрузочное испытание, проверка промышленного SLA или восстановление из резервной копии. Исходные fuzz-примеры входят в обычный go test. Результат vuln относится к базе Go на момент запуска и не является бессрочной гарантией отсутствия уязвимостей.
